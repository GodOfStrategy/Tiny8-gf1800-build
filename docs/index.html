01 / INSIDE THE CPU

A processor, not just an ALU.

Tiny8 combines an 8-bit datapath with instruction decoding, control sequencing, registers, memory access and branching — the essential pieces of a programmable computer.

Eight-bit operations

The ALU supports arithmetic, comparison, bitwise logic, shifts and increment operations. Four status flags track zero, carry, negative and overflow conditions.

Eight general-purpose registers

R0 through R7 provide the CPU's working storage for operands and intermediate results.

02 / MEMORY MAP

One SRAM. Two jobs.

The design integrates a 256 × 8-bit GF180 SRAM macro and divides its address space between program storage and data/stack storage.

Shared SRAM address space256 BYTES TOTAL

Lower 128 bytes: data RAM and stack. Upper 128 bytes: program storage.

Each instruction occupies two bytes. The program counter addresses 64 instruction positions in the 128-byte program region.

03 / INSTRUCTION SET

A purpose-built ISA.

A 16-bit instruction format with a 5-bit opcode field provides 32 possible opcode slots. The instruction set covers computation, data movement, memory, branching and I/O.

04 / PROGRAM LOADING

Program it over SPI.

The SPI programmer turns the chip into a self-contained programmable system: load instruction bytes from a carrier board, then release reset and let the CPU run.

SPI mode 0 · MSB first · 128-byte program capacity · READY handshake · FULL indication

From bytes to execution.

The integrated SPI programmer receives serial data and writes it into the upper half of the shared SRAM. The CPU is held in reset while programming is active, preventing instruction fetches from interfering with writes.

After loading, deassert programming mode and release reset. The processor begins fetching the program from its program region.

05 / VERIFICATION

Tested beyond the RTL.

Verification covered the processor's programming path and execution, followed by gate-level testing through the project workflow.

CPU regression PASSED

Program bytes were loaded through the programming interface. The test checked register results, output value, program counter, instruction register and halted state.

SPI programming test PASSED

The SPI testbench loaded a 10-byte program into SRAM and verified that the CPU executed it and produced the expected result.

Gate-level regression PASSED

The gate-level test completed successfully after correcting the expected bidirectional pin-enable value for the execution-mode interface.

Physical-design workflow COMPLETED

The GitHub workflow completed physical implementation and generated GDS. DRC was also completed successfully.
